# 版本记录：v1.33-gemini-liquid-glass-calendar-refactor

## 1. 本轮目标

根据用户要求，使用 Gemini `gemini-3.1-pro-preview` 对当前日历前端提出重构建议，并将页面进一步调整为更克制、更精美的 Apple 液态玻璃风格。

- `AGENTS.md`
- `custom/notes/v1.32-calendar-real-todo-and-course-schedule.md`

- `custom/notes/v1.30-liquid-glass-calendar-root.md`
- `src/components/CalendarExperience.tsx`
- `src/styles/calendar.css`

未找到 `custom/notes/experiments/` 下相关实验记录。

延续思路：

1. 保留根首页日历应用。
2. 保留真实 Todo、课程、45 分钟时间块和忙碌程度计算。
3. 保留旧站 `/old/` 入口。
4. 保留 30 天、桌面 6 列的核心日历结构。

放弃思路：

1. 放弃大 hero 式首屏。
2. 放弃整张日期卡片用红黄绿大面积铺色。
3. 放弃移动端改成 3 列或 2 列导致星期结构断裂的布局。

## 3. 问题分析

Gemini 反馈当前页面仍有三个主要问题：

1. 首屏仍偏 landing page，工具属性不够强。
2. 红黄绿状态色面积偏大，玻璃质感被任务状态颜色抢走。
3. 移动端缩列后失去日历横向星期结构。

同时，动画可以进一步靠近 Apple 的 spring 质感，详情切换应有明确左右方向，而不是单纯上下淡入。

## 4. 候选方案比较

方案 A：只调整 CSS 颜色和字体。  
优点：改动最小。  
缺点：hero、交互方向和移动端结构问题仍然存在。

方案 B：在现有组件中做小范围结构调整，同时精修样式和动画。  
优点：保留已有数据与业务逻辑，能解决主要视觉问题。  
缺点：仍然没有完全拆分为多个组件和 hook。

方案 C：彻底拆分组件、抽 hook、重写布局。  
优点：架构更清晰。  
缺点：本轮风险和改动面过大，容易影响已验证的日程逻辑。

最终采用方案 B。

## 5. 最终决策

1. 将 `calendar-hero` 改为更紧凑的 `calendar-command`，首屏变成系统工具栏式 dashboard。
2. 日期卡片保持透明玻璃，忙碌程度只通过状态圆点和顶部细线表达。
3. 加入鼠标位置驱动的卡片局部高光。
4. 详情面板切换改为按日期方向左右滑动。
5. 移动端保留 6 列日历，通过横向滚动承载完整星期结构。
6. 字体权重整体下调，标题使用轻微负字距，小标签使用正字距。

## 6. 具体实现

### 6.1 组件

文件：`src/components/CalendarExperience.tsx`

- 新增 `detailDirection`，用于记录详情面板切换方向。
- 新增 `selectDay`，点击不同日期时根据日期索引设置左右方向。
- 新增 `moveDaySpotlight`，用 CSS 变量记录鼠标在日期卡片内的位置。
- `calendar-hero` 改为 `calendar-command`。
- 日期卡片移除旧的 `day-card-glow`，改为 `day-status-dot`。
- Framer Motion 动画统一改为更柔和的 spring 参数。

### 6.2 样式

文件：`src/styles/calendar.css`

- 背景改为更柔和的 mesh gradient，并加入轻微噪点纹理。
- 大光斑改为大尺寸 blur，动画更慢。
- `calendar-command` 压缩高度和间距，减少首屏宣传感。
- 状态色改为 CSS 变量 `--busy-rgb`，用于状态点、细线和轻量阴影。
- 日期卡片主体背景移除忙碌色渐变，保持玻璃透明感。
- 移动端 `.calendar-board` 开启横向滚动，`.day-grid` 和 `.weekday-row` 保持 6 列。

## 7. 本轮优点

1. 页面更像一个 Apple 风格的日程工具，而不是 landing page。
2. 红黄绿语义仍然保留，但不会压过玻璃质感。
3. 详情切换更顺滑，并能感知前后日期方向。
4. 移动端保留星期结构，日历认知更稳定。
5. 真实 Todo、课程和 45 分钟时间块逻辑未被破坏。

## 8. 本轮缺点与代价

1. 没有按 Gemini 建议彻底拆分 hook 和子组件，当前仍是单文件主组件。
2. 移动端横向滚动比 2 列瀑布更接近日历语义，但需要用户横滑查看后几列。
3. 浏览器插件当前视口较窄，本轮视觉截图主要验证了窄屏状态；桌面宽屏仍依赖构建和 CSS 逻辑检查。
