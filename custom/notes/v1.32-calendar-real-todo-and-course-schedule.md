# 版本记录：v1.32-calendar-real-todo-and-course-schedule

## 1. 本轮目标

根据用户提供的 Todo 截图和课表截图，将日历从示例日程升级为真实日程分配：

1. 每个任务时间块按 `45min` 处理。
2. 未完成 Todo 按截止时间和重复规则分配到未来日期。
3. 课表按星期固定加入每天详情。
4. 每天忙碌程度根据课程与任务块重新计算。

## 3. 问题分析

用户需要的不只是“日历壳”，而是把真实课程与 Todo 分配到每一天。核心约束有三点：

1. Todo 中有每天重复任务，也有 ddl 前完成的一次性任务。
2. 一个时间块固定为 45 分钟。
3. 课表是固定占用，需要和任务块一起影响当天忙碌程度。

## 4. 候选方案比较

方案 A：手动写死每天日程。  
优点：最直观。  
缺点：30 天维护成本高，无法适应当前日期滚动。

方案 B：把 Todo 和课表结构化，进入页面后动态生成未来 30 天日程。  
优点：保留“昨天开始”的动态能力，也能自动按规则分配。  
缺点：分配策略仍是启发式，不是完整排课算法。

最终采用方案 B。

## 5. 最终决策

1. 新增 `COURSE_SCHEDULE`，按星期映射课程。
2. 新增 `TODO_BLOCKS`，按用户截图中的未完成 Todo 建立任务块。
3. 新增 `TASK_BLOCK_TIMES`，按星期提供可用 45 分钟任务时段。
4. 日常任务每天重复，一次性任务按截止日前负载较低的日期分配。
5. 已勾选任务视为完成，本轮不再排入未来负载。

## 7. 本轮优点

1. 日历详情不再是示例内容，而是来自用户截图的真实任务与课表。
2. 45 分钟时间块已经体现在每条任务时间上。
3. 课程会稳定出现在对应星期。
4. 红黄绿忙碌程度现在与真实负载相关。

## 8. 本轮缺点与代价

1. 课表截图中个别课程结束时间只能按截图位置近似估计。
2. Todo 分配是启发式，不会像专业排课系统一样做全局最优。
3. 已完成任务没有展示在日历里，只影响不到未来负载。
