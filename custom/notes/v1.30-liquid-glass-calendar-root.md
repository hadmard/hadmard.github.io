# 版本记录：v1.30-liquid-glass-calendar-root

## 1. 本轮目标

把根网址 `https://hadmard.github.io/` 从临时入口页升级为一个交互式日历：

1. 访问根网址后直接看到日历。
2. 日历从“昨天”作为第一天开始排列。
3. 显示约 `6 × 5`，即 30 天。
4. 每天可点击，查看当天详细日程。
5. 每天用类似 macOS 窗口语义的红、黄、绿显示忙碌程度。
6. 视觉风格偏 Apple 液态玻璃，动画尽量丝滑。
7. 旧站继续保留在 `/old/`。

## 3. 问题分析

用户要的是一个首页级应用，而不是普通介绍页。核心难点有三点：

1. “昨天作为第一天”不能写死到静态构建里，否则 GitHub Pages 发布后日期会过期。
2. `6 × 5` 网格需要在桌面端稳定成立，同时在移动端响应式降级。
3. 液态玻璃效果需要兼顾观感和性能，不能为了“玻璃”把页面做成重 blur 滚动灾难。

## 4. 候选方案比较

方案 A：纯 Astro 静态生成日历。  
优点：实现简单，首屏 HTML 完整。  
缺点：昨天日期会绑定构建时间，不适合长期部署。

方案 B：根页加载 React 客户端组件，由浏览器按当前日期生成日历。  
优点：每天访问都会自动从真实昨天开始，交互和动画更自然。  
缺点：首屏需要客户端组件加载。

方案 C：引入完整日历库。  
优点：日历能力成熟。  
缺点：本轮需求是高度定制视觉与 6×5 结构，日历库反而会增加样式改造成本。

最终采用方案 B。

## 5. 最终决策

1. 新增 `CalendarExperience.tsx` 作为根首页日历应用。
2. 新增 `calendar.css` 专门承载液态玻璃视觉。
3. 根页 `src/pages/index.astro` 使用 `client:only="react"` 加载日历，确保日期按访问当天动态生成。
4. 忙碌程度用 `green / yellow / red` 三档保留接口，当前先用日程数量与权重计算，后续可替换为 AI 判定。

## 6. 具体实现

### 6.1 日历组件

文件：`src/components/CalendarExperience.tsx`

实现：

- 进入页面后以浏览器当前日期为锚点，第一天设为昨天。
- 生成 30 个 `CalendarDay`，桌面端按 6 列排列。
- 每天包含：
  - 日期 ID
  - 日期对象
  - 忙碌程度
  - 日程列表
- 点击任意日期后，右侧详情面板切换到该日。
- 详情面板显示：
  - 完整日期
  - 忙碌程度标签
  - 当日摘要
  - 上一天/下一天切换
  - 时间线日程列表

### 6.2 视觉样式

文件：`src/styles/calendar.css`

实现：

- 使用高分辨率径向光斑、网格背景和玻璃面板。
- 面板采用 `backdrop-filter` 与 `-webkit-backdrop-filter`。
- 红、黄、绿忙碌程度对应 Apple/macOS 风格色彩语义。
- 日期卡片使用 GPU 友好的 transform 动画与 hover/tap 反馈。
- 桌面保持 6 列，平板/手机降级为 3 列/2 列。
- 支持 `prefers-reduced-motion`，降低动画敏感用户负担。

### 6.3 根页接入

文件：`src/pages/index.astro`

实现：

- 页面标题改为 `Yfcccc | 日程日历`。
- 删除临时入口页内容。
- 直接加载 `CalendarExperience client:only="react"`。
- 旧版站点仍通过 `/old/` 链接访问。

## 7. 本轮优点

1. 根网址现在直接进入日历，符合用户目标。
2. 日期从浏览器当前日期动态计算，不会因静态构建过期。
3. 桌面端真实验证为 6 列、30 天。
4. 点击日期能切换详情面板，功能闭环成立。
5. 视觉上比普通日历更接近 Apple 液态玻璃界面。

## 8. 本轮缺点与代价

1. 日程数据目前是示例数据，后续需要接入真实日程来源或 AI 判定结果。
2. 液态玻璃效果依赖现代浏览器的 `backdrop-filter`，老设备会退化为半透明面板。
3. 客户端日历需要 React 加载后才完整出现。
