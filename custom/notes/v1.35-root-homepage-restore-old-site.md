## 1. 本轮目标

根据用户要求删除首页的时间表/日程日历功能，让根首页 `/` 回到当前老站首页的内容与信息结构。

延续思路：

2. 保留 `/old/` 下已有子页面，避免破坏现有旧站路径。

2. 放弃 `CalendarExperience` 组件及其专用样式。
3. 放弃将根首页导航指向尚不存在的 `/progress/`、`/projects/` 等新路径。

## 3. 问题分析

用户明确表示不再需要时间表功能，希望首页恢复为老站内容。当前根页直接加载 React 日历组件，这会让访问 `hadmard.github.io/` 时进入日程工具，而不是个人主页内容。

同时，老站的栏目页目前都在 `/old/` 下。如果根首页直接复用 `HomePage` 但不处理导航，导航会指向不存在的根路径。因此需要让根首页显示老站首页内容，同时让导航继续进入已有 `/old/` 子页面。

## 4. 候选方案比较

方案 A：只把根页跳转到 `/old/`。  
优点：改动极小。  
缺点：根首页本身不是内容页，用户访问根网址会多一次跳转。

方案 B：根页直接渲染 `HomePage`，导航继续指向 `/old/`。  
优点：根网址直接显示老站首页内容，同时不需要复制旧页面。  
缺点：根页的导航目标仍在 `/old/` 下，站点结构暂时保持混合状态。

方案 C：把所有 `/old/` 子页面复制到根路径。  
优点：根路径结构最完整。  
缺点：改动面大，容易引入重复页面和后续维护成本。

最终采用方案 B。

## 5. 最终决策

1. 根页 `src/pages/index.astro` 改为加载中文文章并渲染 `HomePage`。
2. `HomePage` 增加 `navBasePath`、`canonicalPath`、`alternatePath` 覆盖能力。
3. 根页使用 `basePath=""` 保持 canonical 为 `/`，同时用 `navBasePath="/old"` 让导航进入已有老站栏目。
4. 删除 `src/components/CalendarExperience.tsx` 和 `src/styles/calendar.css`。

## 6. 具体实现

### 6.1 根页

文件：`src/pages/index.astro`

- 删除日程日历专用 `Layout` 配置。
- 改为读取中文 `thoughts` 集合并渲染共享 `HomePage`。

### 6.2 共享首页组件

文件：`src/components/HomePage.astro`

- 增加 `canonicalPath` 与 `alternatePath` 覆盖参数，避免根页复用旧站导航时 canonical 被写成 `/old/`。

### 6.3 删除日程功能文件

删除：

- `src/components/CalendarExperience.tsx`
- `src/styles/calendar.css`

## 7. 本轮优点

1. 根网址重新回到个人主页内容，符合用户最新方向。
2. 删除了首页日程功能入口，避免继续显示时间表。
3. 没有复制旧站页面，维护成本较低。
4. `/old/` 下已有栏目页继续可用。
