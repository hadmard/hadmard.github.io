大模型的参数可以理解为对于知识量的存储，因此MOE架构实现了计算量减少的同时，增大了知识量的储备

SwiGLU

首先一个FFN是有两个权重矩阵的，因此为2HD个参数

这里的SwiGLU实际上有两个向上的权重矩阵，然后这两个矩阵再做一个hadamard积（类似于门控），然后再乘一个向下的权重矩阵

量化

s_x 类似比例尺吧

这里的激活是指文本的向量化后的结果

权重就是W

计算加速

原始 MoE 程序 每次只算一个数字，速度慢 ↓ 使用 INT8 数字更小，一次可以装更多 ↓ 使用 AVX-512 一个 CPU 核心一次处理一排数字 ↓ 使用 AMX 一个 CPU 核心一次处理一小块矩阵 ↓ 使用 OpenMP 让多个 CPU 核心同时处理不同任务

VNNI 提供专用的指令，来讲多个 INT8 点积 INT8 来累加到INT32，是CPU专门加速INT8点积的一组SIMD指令

AVX-512 内含有ZMM 向量寄存器，可以很快处理向量的运算，512bit的向量寄存器，可以存16个FP32

AMX 内含有TMM Tile 寄存器，可以很快处理矩阵的运算

TMUL 是负责矩阵乘法的硬件计算单元

preprocess ，矩阵在内存里面是一行一行保存，因此每行之间不连续，访存不连续，Cache表现不好

OpenMP

parallel for

一个for循环，正常而言是一个线程串行运行

但是可以使用 #pragma omp parallel for 来实现并行计算，这个分配或许是自动分配的

共享变量和私有变量

所有的线程都可访问的变量即为共享变量，私有是每个线程私有的

多个线程同时访问同一个位置，并且至少有一个线程在写的情况我们叫做数据竞争

reduction

同时累加一个共享变量时候可能会出现一颗偏差，因此可以使用reduction，来创造一个局部环境，分别累加之后再最后加最后的结果

并行浮点数求和

串行和并行的实际加的顺序不一样（小括号的位置），因此舍入后的误差也会有变化

schedule

三种方式

schedule(static)，静态调度

适合每次循环的工作量差不多的情况

schedule(dynamic,chunk)，动态调度

线程做完一小块之后再来领取下一块，让空闲下来的线程能继续领，但是领取时需要运行时管理，不一定比静态快，一般是不同线程的负载很不均衡时候使用

schedule(guided)

折中方案，前期减少调度次数，后期提升负载均衡

负载均衡

就是让每个线程的任务处理时长近似

并行区域

进出并行区域是有损耗哒，所以最好放一起

# pragma omp parallel
{
    #pragma omp for
    for (...) {
    }

    #pragma omp for
    for (...) {
    }

    #pragma omp for
    for (...) {
    }
}
