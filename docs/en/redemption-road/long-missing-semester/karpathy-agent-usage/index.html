Software 1.0、2.0 与 3.0

Software 1.0 是传统编程：人类将解决问题的规则明确写成代码。

Software 2.0 不再直接编写规则，而是通过数据集、训练目标、损失函数和神经网络结构进行“编程”，最终得到的模型权重相当于程序。

Software 3.0 则把大语言模型看作一种新的可编程计算机。人类主要通过自然语言、上下文、示例、工具和反馈来控制模型完成任务。因此，Software 3.0 并不等于 vibe coding，vibe coding 只是其中一种使用方式。

Software 3.0 的意义也不只是让原来的代码写得更快。随着神经网络承担越来越多的信息处理工作，一些过去需要复杂软件流程完成的任务，现在可能只需要输入数据和一段指令。未来的变化不仅是“更快地开发原有软件”，也包括重新思考哪些软件仍有存在的必要。

Vibe Coding 与 Agentic Engineering

Vibe coding 提高了软件创造的下限。 即使缺少专业编程经验，普通人也可以通过自然语言快速做出网页、工具或应用。

但它提高的主要是“创造软件结果的能力”，并不一定提高使用者真正的编程知识。软件能够运行，也不代表其架构、安全性和可维护性达到了专业标准。

Agentic engineering 则是在使用 agent 提高效率的同时，继续维持专业软件的质量标准。 即使大量代码由 agent 生成，工程师仍然需要对正确性、安全性、性能和可维护性负责。

两者最核心的区别可以概括为：

Vibe coding 关心的是软件能否被快速做出来； Agentic engineering 关心的是软件能否被快速、正确并可靠地做出来。

Agentic Engineering 是一种新的工程学科

Agent 并不是普通的编程工具。它能力强大，却同时具有随机性、容易犯错，而且在不同任务上的能力非常不均衡。

因此，如何拆分任务、管理上下文、设计规格、设置权限、建立测试和验证机制，并监督多个 agent 协同工作，正在逐渐形成一套新的工程方法。

Agentic engineering 的能力上限也非常高。过去人们讨论“10×工程师”，但在 agent 时代，真正擅长组织和监督 agent 的工程师，其产出规模和能够处理的项目复杂度可能远远超过传统的十倍概念。

AI 一方面降低了软件开发的门槛，另一方面也可能放大专业工程师之间的差距。Vibe coding 提高下限，而 agentic engineering 提高上限。

从 Plan 转向 Specification

人与 agent 合作时，重要的不只是让 agent 先生成一份简单计划。

Plan 主要回答“接下来按什么步骤做”，而 specification 则需要明确：

  • 最终系统应该实现什么；

  • 系统需要遵守哪些约束；

  • 哪些行为绝对不能发生；

  • 如何判断任务是否真正完成。

更成熟的工作方式，是人与 agent 共同形成详细的规格说明，然后由 agent 完成大量实现工作，人类负责监督、审查和修改。

人的角色：从写代码转向设计和监督

当前的 agent 更像一个能力很强但不稳定的实习生。它可以快速查找 API、生成代码和处理实现细节，却可能在系统设计和业务逻辑上犯下很基础的错误。

因此，人的工作正在从亲自完成每个细节，转向：

  • 定义真正的问题；

  • 建立正确的系统抽象；

  • 设计架构和边界；

  • 提出约束和验收标准；

  • 判断结果是否合理；

  • 监督并修正 agent。

未来，记忆 API 和语法细节的重要性会下降，但理解底层原理、数据模型、系统设计和安全边界的重要性会进一步上升。

Agent 生成的代码也经常存在膨胀、重复、抽象脆弱等问题。它通常擅长让程序通过测试，却未必擅长写出简洁、优雅且长期可维护的代码。因此，工程品味和代码审查仍然是人的重要责任。

理解不能被外包

Karpathy 引用了一句话：

You can outsource your thinking, but you can’t outsource your understanding.

也就是：

你可以把部分思考过程外包给 AI，但不能把理解本身外包出去。

Agent 可以帮助人搜集信息、生成方案、编写代码和运行实验，但人仍然必须理解自己正在解决什么问题、为什么这个问题值得解决，以及什么样的结果才是正确的。

如果缺少理解，人就无法判断 agent 是真正解决了问题，还是只是生成了一个看起来合理的答案。

因此，未来优秀程序员的核心竞争力，不再只是亲手写出每一行代码，而是能够理解复杂系统、制定正确规格、组织 agent 工作，并验证最终结果。
