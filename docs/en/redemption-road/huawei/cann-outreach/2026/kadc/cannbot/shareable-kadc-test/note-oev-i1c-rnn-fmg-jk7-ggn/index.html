1. 调优方法论总览

Profiling 采集 → 瓶颈识别 → 按瓶颈分类优化 → 验证迭代

核心原则：数据驱动，先定位瓶颈再优化，避免凭直觉盲改。

2. 瓶颈识别

通过 Profiling 数据分析 PipeUtilization.csv 中各单元的时间占比，确认主导瓶颈。

2.1 瓶颈分类速查

瓶颈类型判定条件优化方向
VEC Boundaiv_vec_ratio 最高且 >50%减少计算量、UB 融合、融合指令
MTE2 Boundai*_mte2_ratio 最高增大搬运粒度、地址对齐、DoubleBuffer
CUBE Boundaic_cube_ratio 最高L0C 累加、L1 复用、AtomicAdd
SCALAR Boundai*_scalar_ratio >30%缩小 TilingData、减少核数
流水线气泡多单元均在 30-50%，无明显主导增加 workspace、DB、异步迭代
核间不均衡各核耗时差异 >10%均匀分配尾块、调整 Block Dim

2.2 交叉关联诊断

3. VEC Bound（Vector 计算瓶颈）优化

3.1 严重程度

  • 50-65%：轻度，DoubleBuffer + UB 融合有较大收益
  • 65-80%：中度，需减少 Cast 或融合指令
  • >80%：深度，VEC 接近理论极限，优化空间有限

3.2 优化方法（按优先级）

#方法预期收益适用条件
1UB 融合20-50%多步计算间有 GM 往返
2减少 Cast10-30%fp32 ratio 远高于预期（大量 fp16→fp32 转换）
3融合指令5-15%存在 mul+add、mul+sub 等可融合序列
4低延迟归约10-20%有 ReduceSum/Max 操作
5AIC:AIV = 1:230-40%MatMul 后带 Vector 后处理
6Counter 模式5-10%循环内有条件判断

3.3 UB 融合

将多次 GM↔UB 往返合并为一次，减少带宽压力：

未融合: GM→UB→Compute1→UB→GM→UB→Compute2→UB→GM  // 6 次 GM 访问
已融合: GM→UB→Compute1→Compute2→UB→GM             // 2 次 GM 访问

3.4 减少 Cast

  • 如果算子精度允许，直接用 fp16 计算避免 fp16→fp32 转换
  • 必须转换时，尽量批量一次转换，避免逐元素 Cast

4. MTE2 Bound（搬入瓶颈）优化

4.1 先判断是否已达理论带宽

理论 MTE2 耗时 = GM_to_UB_datas(KB) × 1024 / GM_峰值带宽(Byte/s)
实际 MTE2 耗时 = ai*_mte2_time(us)

if 实际 ≈ 理论 (差异<20%):
    MTE2 已达上限 → 优化方向是流水编排（掩盖搬运）
else:
    MTE2 未达上限 → 检查搬运效率

4.2 优化方法

#方法适用条件检查方式
1增大单次搬运量单次 <16KB计算 GM_to_UB_datas / mte2_instructions
2512B 地址对齐fixpipe_ratio >5%检查 aic_fixpipe_ratio
3L2 CacheModeL2 hit rate <50%检查 L2Cache.csv
4避免同地址访问多核读同一地址检查各核 mte2_time 差异大
5DoubleBufferMTE2 和 VEC 串行流水图显示无重叠
6增大 Tile 尺寸搬运次数过多mte2_instructions 过大

4.3 L2 Cache 优化

#方法说明
1设置 CacheModeSetL2CacheHint(CacheMode::CACHE_MODE_NORMAL) 启用 L2 缓存
2禁用不需要的缓存只读一次的数据设置 CACHE_MODE_DISABLE 避免污染 L2
3L2 Cache 切分合理规划数据搬运顺序，提高数据局部性
4较小矩阵驻留 L1MatMul 场景中，让 B 矩阵驻留 L1，减少 GM 访问

5. CUBE Bound（矩阵计算瓶颈）优化

#方法说明
1L0C 累加利用 L0C 做多次矩阵乘法的累加，减少搬运
2L1 数据复用合理 Tiling 使 A/B 矩阵驻留 L1，减少 GM 访问
3BT Buffer使用 BT Buffer 实现高效 bias 计算
4FP Buffer使用 FP Buffer 存放量化参数
5AtomicAddMatmul 使能 AtomicAdd 选项优化多核

6. SCALAR Bound（标量计算瓶颈）优化

通常出现在数据量很小、头开销占比大的场景。

#方法说明
1缩小 TilingData减少不必要字段，TilingData 越大搬运越慢
2减少核数数据量小时，少核 = 少头开销
3TPipe 外置避免 TPipe 在对象内创建和初始化
4移出不变量循环不变的计算移到 Host 侧

头开销参考值

平台满核头开销说明
Atlas A2~20-21 us包含核启动 + TLB + 初始化

如果 Task Duration 中头开销占比 >30%，说明数据量太小或核数太多。

7. 核间负载不均衡优化

7.1 诊断

# 从 PipeUtilization.csv 提取各核耗时
times = [row['aiv_time(us)'] for row in pipe_rows]
imbalance = (max(times) - min(times)) / max(times) * 100

if imbalance < 10:   print("均衡")
elif imbalance < 30:  print("不均衡，调整 Tiling")
else:                 print("严重不均衡，优先修复")

7.2 优化方法

方法说明
均匀分配尾块数据总量不能被核数整除时，将尾块分散到更多核
调整 Block Dim选择能整除数据量的核数
尾块调整策略kernel 中动态计算尾块的实际大小，而非用满块大小搬运

7.3 尾块正确处理

// 方式1：循环内动态计算尾块大小
for (uint32_t k = 0; k < totalK; k += BLOCK_SIZE) {
    uint32_t actualSize = (k + BLOCK_SIZE <= totalK) ? BLOCK_SIZE : (totalK - k);
    DataCopyPad(dst, src[k], actualSize);
}

// 方式2：先计算 loops，循环末尾单独处理尾块
uint32_t kLoops = (totalK + BLOCK_SIZE - 1U) / BLOCK_SIZE;
uint32_t kBlockSize = BLOCK_SIZE;
for (uint32_t i = 0; i < kLoops; i++) {
    if (i == kLoops - 1U) {
        kBlockSize = totalK - (kLoops - 1U) * BLOCK_SIZE;
    }
    DataCopyPad(dst, src[i * BLOCK_SIZE], kBlockSize);
}

8. Bank Conflict 优化

8.1 判定

ResourceConflictRatio.csv 中 aiv_vec_total_cflt_ratio >5%

8.2 UB Bank 结构

  • UB: 48 个 bank，分为 16 个 group（每组 3 个 bank）
  • 每个 bank 32 Bytes 宽
  • 同时读写同一 bank → bank conflict
  • 同时读同一 bank group 的不同 bank → bankgroup conflict

8.3 按冲突类型优化

冲突类型判定字段原因优化
bankgroupvec_bankgroup_cflt_ratio >3%block_stride 设置不合理修改 Vector API 的 repeatStride/blockStride 参数
bankvec_bank_cflt_ratio >3%操作数读写指针地址不合理调整 UB tensor 起始地址，添加 padding（32B 整数倍间隔）
资源vec_resc_cflt_ratio >5%多个计算单元争抢同一执行单元错开 Vector/Cube 调度
MTEvec_mte_cflt_ratio >3%Vector 和 MTE 竞争共享资源调整数据搬运和计算时序

9. DoubleBuffer 优化

9.1 原理

时间 →
Buffer 0: [MTE2搬运]──[Vector计算]──[MTE3写出]
Buffer 1:        [MTE2搬运]──[Vector计算]──[MTE3写出]
                  ↑ 搬运和计算并行！

9.2 检查清单

#检查项正常值
1InitBuffer 的 bufNum 参数是否为 2必须为 2
2EnQue/DeQue 是否正确配对每次循环都有
3循环内是否有不必要的 Sync应避免
4数据依赖是否阻止了并行检查前后 tile 是否有依赖

9.3 效果验证

状态MTE2 和 VEC 重叠比例
DB 生效>30%
DB 部分10-30%
DB 未生效<5%

9.4 使用方式

constexpr uint32_t BUFFER_NUM = 2;  // 双缓冲
pipe.InitBuffer(inQueueX, BUFFER_NUM, tileLength * sizeof(T));
pipe.InitBuffer(inQueueY, BUFFER_NUM, tileLength * sizeof(T));
pipe.InitBuffer(outQueue, BUFFER_NUM, tileLength * sizeof(T));

适用条件：数据量较大（>8K 元素）、搬运和计算时间相当、UB 容量允许双缓冲。

10. 流水线气泡优化

多个单元均在 30-50% 占比，无明显主导单元时，说明存在流水线气泡。

#方法说明
1增加 workspace 份数从 2 份增到 4 份，减少 Cube/Vector 互等
2DoubleBuffer使搬运和计算并行
3异步迭代使用 IterateAll/EnQueAll 减少同步开销
4AIC:AIV 比例调整Cube 和 Vector 耗时不匹配时调整启动比例

11. 通用代码级优化规范

11.1 循环内禁止逐元素操作

逐元素 API 调用会产生严重的调用开销：

// 错误：循环内逐行调用 API
for (uint32_t r = 0; r < R; r++) {
    AscendC::Sub<float>(xLocal[r * alignedCols], xLocal[r * alignedCols],
                        tmpLocal, cols);
}

// 正确：使用批量操作
AscendC::Sub<float>(xLocal, xLocal, tmpLocal, totalSize);

11.2 禁止写死硬件参数

// 错误：写死核数
uint32_t blockDim = 24;

// 正确：动态获取
uint32_t blockDim = GetBlockDim();

11.3 减少冗余 PipeBarrier

连续 Vector 操作之间不需要 PipeBarrier（硬件保序），只在跨 Pipe 依赖时才需要：

场景是否需要 Barrier
DataCopy(GM→UB) 后 Vector 计算需要（通过 EnQue/DeQue）
Vector 计算后 DataCopy(UB→GM)需要（通过 EnQue/DeQue）
连续 Vector 操作不需要（硬件保序）
Reduce 后读标量需要

11.4 单次搬运量 >= 16KB

constexpr uint32_t TILE_SIZE = 16 * 1024 / sizeof(float);  // >= 16KB

11.5 避免 GM 重复读取

在 UB 中缓存数据，避免对同一 GM 地址多次 DataCopy。

11.6 流水线同步正确性

DataCopy 是异步 DMA，必须通过 EnQue/DeQue 同步：

// Step 1: CopyIn
LocalTensor<float> xLocal = inQueueX.AllocTensor<float>();
DataCopyPad(xLocal, xGm[gmOffset], copyParams, padParams);
inQueueX.EnQue(xLocal);                    // 标记就绪

// Step 2: Compute
LocalTensor<float> xIn = inQueueX.DeQue<float>();  // 阻塞等待 MTE2 完成
Adds<float>(yLocal, xIn, 1.0f, count);
outQueueY.EnQue(yLocal);

// Step 3: CopyOut
LocalTensor<float> yOut = outQueueY.DeQue<float>();  // 阻塞等待 Vector 完成
DataCopyPad(yGm[gmOffset], yOut, copyParams);

11.7 FP16 中间精度保护

FP16 精度有限（约 3 位有效数字），累加/归约操作应使用 FP32 中间结果：

// 正确：使用 FP32 累加
float sum = 0;
for (int i = 0; i < N; i++) {
    sum += (float)data[i];  // FP32 累加
}
half result = (half)sum;  // 最后转回 FP16

12. Tiling 设计优化

12.1 多核切分策略

  • 负载均衡：每个核处理的任务量尽量相等
  • 数据局部性：相邻数据尽量分配给同一核
  • 粒度适中：tile 不能太小（调度开销大），不能太大（并行度低）
// 均匀切分 + 处理余数
uint32_t totalLength = ...;
uint32_t blockDim = GetBlockDim();
uint32_t avgLength = totalLength / blockDim;
uint32_t remainder = totalLength % blockDim;

uint32_t tileLength = avgLength + (blockIdx < remainder ? 1 : 0);
uint32_t offset = blockIdx * avgLength + std::min(blockIdx, remainder);

12.2 片上缓存容量约束

各级缓存容量固定，Tiling 时必须确保不超限：

缓存所属核典型容量用途
UBVector Core256 KB (DAV_3510)向量计算缓冲
L1Cube Core512 KB (DAV_3510)GM→L1 数据缓存
L0ACube Core64 KB矩阵左输入
L0BCube Core64 KB矩阵右输入
L0CCube Core256 KB矩阵乘输出
  • 纯向量算子：所有 InitBuffer 的 bufferNum × bufferSize 之和不超过 UB 容量
  • 矩阵算子：额外检查 L1、L0A/L0B/L0C 各级分配

12.3 Buffer 规划原则

Buffer 类型推荐配置
输入 Buffer2 个（Double Buffer）
输出 Buffer2 个（Double Buffer）
临时 Buffer按需分配
Reduce 临时 Buffer额外分配

13.5 MatMul 精度常见陷阱

现象根因修复

15. 调优检查清单

性能优化

  • 循环内是否有逐元素 API 调用？（PERF-1）
  • 是否写死了核数或 UB 大小？（PERF-2）
  • 大数据量是否使用 Double Buffer？（PERF-3）
  • PipeBarrier 是否过多或过少？（PERF-4）
  • 单次搬运量是否 >= 16KB？（PERF-5）
  • 是否有 GM 重复读取？（PERF-6）
  • 尾块的搬运长度是否单独计算？（PERF-7）

精度

  • DataCopy 后是否有同步（EnQue/DeQue）？（PREC-1）
  • 除法/求余是否有除零保护？（PREC-2）
  • FP16 累加是否使用 FP32 中间结果？（PREC-3）

Tiling

  • 各核负载是否均衡？（TIL-1）
  • 各级片上缓存（UB/L1/L0A/L0B/L0C）分配是否溢出？（TIL-2）
  • Buffer 规划是否合理？（TIL-3）

MatMul 专项

  • cmatrixInitVal 是否仅在首拍为 true？
  • BLOCK_CUBE_L0C 是否硬编码为 16？
  • layout 是否与 trans 标志同步？
  • HALF_L0C_SIZE 是否多除了 sizeof？
  • Params 字段顺序与 kernel 声明是否一致？
