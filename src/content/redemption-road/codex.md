# Codex 使用指北

## 安装Codex

有四种方式可以使用codex

1. Codex App
   - 适合那些不太需要详细调整细节的项目，应该也是最广泛的使用方式，使用门槛低，功能多
   - 科研而言，不太推荐使用，因为没法定位细节
2. IDE extension
   - 目前我主要使用这种方式
   - 操作类似 Copilot
3. terminal CLI 版本
   - 很多比较专业的程序员会使用这个方式
   - 没有 GUI 的服务器也可以使用（但是2也可以配置后使用）
   - 有点不直观，我不太喜欢使用，比如说每次调用历史记录需要  `/resume` , 1或者2则一览无余
4. 网页版
   - 只能编辑 `github` 仓库，也许没电脑时候可以替代？
   - 最少使用的一档

## 使用技巧

### Chat bot with coding skill

此不必多言，codex可以根据项目里的实际情况来交互问答



### Prompt

大模型发展初期，Prompt 工程一度很火热。然而随着ai能力的发展，迄今为止，其功能弱化了许多。这里其实不太算提示词工程，只能说是给 ai 的一些约束吧

一个好的提示词可以浓缩成四件事：

1. Goal：你要它做什么
2. Context：参考那些文件
3. Constraints：不能动什么文件
4. Done when：指标（量化更好，如果有的话）



### Agents.md

可以理解为一般性的上者👆

有两个级别

- 一个是所有项目都适用的，这个一般放一些语言风格之类的，泛用性强的

- 一个是一个项目所有对话都适用的，更有对策性



一般可以写一写项目的背景，你想往哪方面去做

或者让codex看完项目之后问你问题，然后综合和他的对话写 agents.md，写完之后也可以让codex再润色一下

**最好让ai每完成一次对话，都将结果记录下来，并且让其每次在开始某个任务之前先广泛参考之前的记录**

个人觉得此还是很重要的，一个好的 Agents.md 可以极大提升开发效率



### `/plan`

做之前和你协商计划，一般适用于任务量稍大，并且需要精细化操作的任务，能了解细节及时跟进



### `/goal`

如果项目有明显的量化指标，可以尝试这个操作。原理就是一次对话结束，把结果和你的目标比较一下，如果没有达到目标，那么就把事先写好的提示词再发送一遍。但是挺费Token的，因为正常的对话完之后，我们会人工对其结果校正思考。但是此模式就完全是自己思考，有时候还是有些幻觉发生。



### 额外的小tips

推荐每次开始一个新的项目的时候先 `git init` ,一方面是方便进行项目版本管理，另一方面是如果没有创建仓库，那么codex所做的操作将无法回退



## Codex特性

### 沙箱

| 模式                 | 含义                                   | 适合                   |
| -------------------- | -------------------------------------- | ---------------------- |
| `read-only`          | 可读文件，但不能直接写或运行需权限命令 | 解释、审查、规划       |
| `workspace-write`    | 可在 workspace 内读写，常规命令可执行  | 日常开发默认选择       |
| `danger-full-access` | 无沙箱限制                             | 只在外部隔离环境中使用 |

| 审批策略     | 行为                                   |
| ------------ | -------------------------------------- |
| `untrusted`  | 只自动运行已知安全的只读命令，其他要问 |
| `on-request` | 沙箱内自动运行，越界时询问             |
| `never`      | 不弹审批，尽力执行                     |



### Agents.md

Codex 会按层次加载指导：

1. 全局 `~/.codex/AGENTS.override.md` 或 `~/.codex/AGENTS.md`。
2. repo 根目录到当前目录沿途的 `AGENTS.override.md`、`AGENTS.md`。
3. 其他指导文件。



### 配置文件

个人默认配置在：

```text
~/.codex/config.toml
```

项目配置在：

```text
.codex/config.toml
```



### Skills

Skill 是可复用工作流，通常是一个包含 `SKILL.md` 的目录。Codex 先看到 skill 名字和描述，只有匹配任务时才读取完整说明，年初爆火的 openclaw 进行功能扩展时候就是一般使用 Skill 来进行



### MCP

MCP 是连接外部工具和上下文的标准协议。Codex 作为 host，通过 MCP client 连接 MCP server。

MCP server 可以提供：

- Tools：可执行动作。
- Resources：可读资料。
- Prompts：可复用模板。



### Plugins

Plugin 是可安装分发单位，可以打包：

- skills。
- app integrations。
- MCP servers。
- lifecycle hooks。
- assets 和元数据。



### Subagent

就是同时让多个agent处理任务，需要在提示词中主动说才可唤出来



### 远程连接

可以实现手机控制电脑的 codex进行任务执行



### In-app browser

内置浏览器，此处指的是 APP 版本的，如果做网站之类的会比较方便看预览



### Chrome extension

可以控制浏览器页面



### Computer Use

可以控制电脑，win端不清楚是否可以，mac端可以实现，但是会有bug
